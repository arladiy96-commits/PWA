# ГрузКонтроль · тестовая PWA

Копия кабинетов из `app (12).zip` от 12.11.2026. Разрабатывается независимо от рабочего JustRun.

## Два режима, один интерфейс

**test (по умолчанию):** выбор кабинета, локальная SQLite-база в IndexedDB. Python-правила из исходного сервера исполняются в отдельном Web Worker через Pyodide. Суммы, тарифы, состояния, права, журнал, ведомости, откат и повторная сдача вычисляются исходными функциями, а не переписанной приблизительной JS-моделью. Никаких запросов к JustRun/Telegram. Тестовые кабинеты используют одну базу на одном origin/устройстве; разные устройства не синхронизируются. Первоначально база пустая, продукция — Мука и Отруби; добавьте грузчиков и тарифы. Есть отдельная тестовая заявка для проверки админского доступа.

**server:** только HTTP-клиент. Бизнес-логика, права, расчёты и данные принадлежат серверу. При сборке каталог `testing`, Python/WASM, локальная база и тестовый адаптер исключены физически. Ошибка сети никогда не включает тестовый режим; очереди локальных записей и скрытой синхронизации нет. Тестовые данные не переносятся.

Первая тестовая загрузка около 19 MiB (Python runtime и шрифт), последующие — из кеша. Перед отключением сети дождитесь «Готово оффлайн». Документы сохраняются по отдельной кнопке «Сохранить / открыть», чтобы работать и на iOS. Telegram-доставка и резервирование рабочего сервера в тесте недоступны; локальную базу можно скачать в админке. Очистка данных браузера удалит тестовую базу. Для одного тестового набора пользуйтесь установленной PWA; отдельные браузеры могут иметь разные хранилища.

## Запуск

Python 3.12+, Node.js 22+.

```sh
python -m venv .venv
. .venv/bin/activate
pip install pytest fastapi httpx reportlab xlsxwriter python-docx
npm ci
python tools/build.py
npm run preview
```

Открыть http://localhost:8765. Для установки на телефон нужен HTTPS.

```sh
pytest -q src/testing/source/tests
node tests/runtime.cjs
python tests/check_build.py
npx playwright install chromium webkit
npm run test:browser
```

CI прогоняет исходные серверные тесты, WASM-сценарии и браузерные сценарии Chromium/WebKit перед публикацией. `check_build.py` проверяет AST-совпадение ключевых функций и отсутствие локального движка в серверной сборке.

## GitHub Pages

В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**. Workflow `Test and publish PWA` собирает и публикует только после успешных тестов. Если Pages ещё не включён, этап build сохранит сборку, а deploy потребует включения Pages и повторного запуска. Рабочий JustRun не изменяется.

## Будущее подключение к серверу

```sh
PWA_MODE=server PWA_API_BASE=https://YOUR-SERVER python tools/build.py
```

**Это подготовленный контракт, а не уже работающий вход в текущем архиве.** В архиве поддерживается только `X-Telegram-Init-Data`. Перед реальным подключением на сервере потребуются:

- `POST /api/auth/login` с `{login, password}` → `{access_token}`; `POST /api/auth/logout` отзывает сеанс.
- `Authorization: Bearer ...` для существующих API, файлов и `/api/events`; `/api/me` сохраняет существующий формат. Идентификация связывается с существующим пользователем и серверными правами, без смены модели расчёта/данных.
- CORS для точного адреса PWA, включая preflight, Authorization, Content-Type, нужные методы; `Access-Control-Expose-Headers: Content-Disposition` для файлов.
- Проверка блокировки пользователей, срока/отзыва сеансов и всех ролей на сервере, проверка совместимости endpoints и отдельный прогон интеграционных сценариев. Серверные пути входа при необходимости настраиваются в `tools/build.py`.

Пароли не сохраняются; токен сеанса — sessionStorage. Серверные API не кешируются service worker. В серверном режиме без сети доступна оболочка, операции требуют сервера.

## Структура

- `src/static/` — адаптированные оригинальные интерфейсы, отдельные файлы по ролям.
- `src/client/` — запуск, выбор кабинета/вход, два независимых адаптера.
- `src/testing/source/` — неизменённый исходник и тесты для воспроизводимости правил; без базы и секретов.
- `src/testing/engine/` — браузерная граница HTTP и локальное хранение; сетевые/ботовые функции исходника не входят в исполняемый модуль.
- `tools/build.py` — статическая сборка, извлечение Python-функций, локальная упаковка зависимостей и кеша.
- `src/sw.js` — кеш только собственных статических файлов, исключающий API.

Никакого токена бота, `.env` и рабочей базы в репозитории нет. Зависимости загружаются при сборке; установленное приложение не требует внешнего CDN. Лицензия шрифта: `assets/FONT-LICENSE.txt`; Python/Pyodide и сторонние пакеты сохраняют свои лицензии.
